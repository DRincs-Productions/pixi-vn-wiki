<Accordion title="What is a `knot`?" id="what-is-a-knot">

As explained in the [official documentation](https://www.inklestudios.com/ink/web-tutorial/), the story is comprised of multiple linked sections which we call `knots` in ***ink* terminology**. The start of a `knot` is indicated in ***ink*** using at least two equals signs on the left hand side of the `knot`'s name, and optionally on the right too.

```ink tab="ink"
=== london ===
```

```txt tab="CLI"
=== <knot_name> ===

where:
    knot_name = the name of the knot
```

</Accordion>

<Accordion title="Are there differences between `label` and `knot`?" id="label-vs-knot">

No, they are the same thing. In Pixi’VN, when you create a `knot` with ***ink***, a `label` will be created internally and saved in the registry.

</Accordion>

</Accordions>

## Run a knot

To run a `knot` you can use the following methods:

<Accordions>

<Accordion title="Diverts `-> start` (jump a `label`)" id="jump">

You can execute a `knot` using the Divert operator, which is represented by the `-> start` syntax. It corresponds to the <DynamicLink href="/start/labels#jump-to-a-label">`jump` functionality</DynamicLink> in the Pixi’VN library.

```ink tab="ink"
-> after
```

```txt tab="CLI"
-> <knot_name>

where:
    knot_name = the name of the knot to jump to
```

Ad esempio:

```ink title="ink/start.ink"
=== start ===
Start
-> after

=== after ===
After
End
-> DONE
```

<NativeJumpExample />

</Accordion>

<Accordion title="Tunnels `-> start ->` or Threads `<- start`  (call a `label`)" id="call">

You can execute a `knot` using the Tunnels operator, which is represented by the `-> start ->` syntax. It corresponds to the <DynamicLink href="/start/labels#call-to-a-label">`call` functionality</DynamicLink> in the Pixi’VN library.

```ink tab="ink"
-> guard_dialogue ->
```

```txt tab="CLI"
-> <knot_name> ->

where:
    knot_name = the name of the knot to call
```

Or, using the Threads syntax, write the `\<-` symbol followed by the name of the `knot`:

```ink tab="ink"
<- guard_dialogue
```

```txt tab="CLI"
<- <knot_name>

where:
    knot_name = the name of the knot to call
```

:::tip[Threads]

Unlike **native ink**, in **ink + Pixi’VN integration** "Threads" are not supported, so the `\<-` symbol corresponds to calling a `knot` instead of being a "Thread" operator.

:::

:::tip

For simplicity, in **ink + Pixi’VN integration**, `->->` and `-> DONE` will correctly close the `label`, so they are equivalent.

:::

Ad esempio:

```ink title="ink/start.ink"
VAR reputation = 0

-> start
=== start ===
You are in the square.

* [Talk to the guard]
    -> guard_dialogue ->
    You return to the square.
    -> start
    You don't see this line because you are sent back to the city before.

* {reputation >= 1} [Ask for a favor]
    The guard helps you.
    -> END

=== guard_dialogue ===
The guard looks at you.

* [Greet]
    "Hello citizen."
    ~ reputation += 1
->->

* [Insult]
    "Hey you!"
    ~ reputation -= 1

->->
```

## Altre funzionalità

<Accordions>

<Accordion title="Parametri" id="parameters">

A particularly useful form of temporary variable is a **parameter**. Any knot or stitch can receive a value as a parameter, which is treated as a local temporary variable inside that knot:

```ink title="ink/start.ink"
=== start ===
*   [Accuse Hastings]
        -> accuse("Hastings")
*   [Accuse Mrs Black]
        -> accuse("Claudia")
*   [Accuse myself]
        -> accuse("myself")

=== accuse(who) ===
    "I accuse {who}!" Poirot declared.
    "Really?" Japp replied. "{who == "myself":You did it?|{who}?}"
    "And why not?" Poirot shot back.
```

Parameters are the correct way to pass a temporary value from one knot or stitch into another, because ordinary `temp` variables are not accessible outside the stitch where they were declared.

</Accordion>

<Accordion title="Recursive knots with parameters" id="recursive-knots-with-parameters">

Temporary variables (including parameters) are safe to use in recursive knots:

```ink title="ink/start.ink"
-> add_one_to_one_hundred(0, 1)

=== add_one_to_one_hundred(total, x) ===
    ~ total = total + x
    { x == 100:
        -> finished(total)
    - else:
        -> add_one_to_one_hundred(total, x + 1)
    }

=== finished(total) ===
    "The result is {total}!" you announce.
    -> END
```

</Accordion>

<Accordion title="Sending divert targets as parameters" id="sending-divert-targets-as-parameters">

Knot addresses can also be passed as parameters. Use `->` to indicate that a parameter is a divert target:

```ink title="ink/start.ink"
=== sleeping_in_hut ===
    You lie down and close your eyes.
    -> generic_sleep(-> waking_in_the_hut)

=== generic_sleep(-> waking) ===
    You sleep perchance to dream etc. etc.
    -> waking

=== waking_in_the_hut ===
    You get back to your feet, ready to continue your journey.
```

</Accordion>

<Accordion title="Diverting in the same `step`" id="diverting-in-the-same-step">

By default, a divert to another `knot` is executed in the next `step`, so the diverted content is shown only after the flow continues:

```ink title="ink/start.ink"
=== start ===
It is, first and foremost...
-> add2

=== add2 ===
...a story about the twelve labors of Hercules.
-> DONE
```

If the divert is placed right after the text, with no line break in between, the diverted `knot` is executed in the same `step` as the preceding text, so both are shown together:

```ink title="ink/start.ink"
=== start ===
It is, first and foremost...-> add2

=== add2 ===
...a story about the twelve labors of Hercules.
-> DONE
```

</Accordion>
