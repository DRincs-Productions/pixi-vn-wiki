## Comment utiliser un template

Vous consultez cette page parce que vous avez probablement déjà créé un projet à partir d'un template. Les sections suivantes vous guideront dans les premières étapes pour le faire fonctionner.

### Configuration initiale

Ouvrez le dossier du projet dans votre IDE. Les exemples ci-dessous utilisent [Visual Studio Code](https://code.visualstudio.com/).

Une fois le projet ouvert, VS Code proposera automatiquement plusieurs actions :

* **Installer les extensions recommandées** — une notification vous invitera à installer les extensions recommandées pour l'espace de travail. Il est vivement conseillé d'accepter. Si cette notification ne s'affiche pas, installez-les vous-même depuis le panneau Extensions en affichant les [extensions recommandées](https://code.visualstudio.com/docs/editor/extension-marketplace#_recommended-extensions).
* **Exécuter les tâches de démarrage** — VS Code peut vous proposer d'exécuter les tâches de démarrage configurées, qui installeront toutes les dépendances du projet. Pour le faire vous-même, lancez :

```npm
npm install
```

:::warning[Multiplateforme]

Si vous avez choisi un template destiné aux plateformes de bureau ou mobiles, vous devrez installer les dépendances supplémentaires requises par [Tauri](https://v2.tauri.app/start/prerequisites/) (chaîne d'outils Rust et outils de compilation propres à chaque plateforme). Comme Tauri s'intègre étroitement à l'environnement système, vous devrez probablement **redémarrer VS Code une ou plusieurs fois** avant de pouvoir lancer le projet comme application de bureau.

:::

### Lancer le projet

Le template comprend plusieurs **configurations de lancement** préconfigurées pour VS Code. Si vous ne les connaissez pas, les configurations de lancement sont des raccourcis qui indiquent à VS Code comment démarrer votre projet (et éventuellement y attacher un débogueur), pour éviter de saisir des commandes dans le terminal à chaque fois. Vous pouvez y accéder depuis le panneau **Exécuter et déboguer** (l'icône de lecture dans la barre latérale gauche, ou en appuyant sur `F5`). Sélectionnez la configuration souhaitée dans le menu déroulant en haut du panneau, puis cliquez sur le bouton de lecture vert.

![Panneau Exécuter et déboguer](/launch-configuration-dropdown.png)

Les configurations suivantes sont disponibles :

* **Debug Game** : c’est la configuration que vous utiliserez le plus souvent pendant le développement : chaque fois que vous enregistrez un fichier, le navigateur s’actualise automatiquement. Notez que, dans ce mode, les animations peuvent être moins fluides et le chargement des assets plus lent que dans la version finale publiée.
* **Debug Game Preview** : cette configuration simule fidèlement le comportement du jeu après publication : les animations sont fluides, les temps de chargement réalistes et les optimisations actives. Utilisez cette configuration pour vérifier que tout s'affiche et fonctionne comme prévu avant la publication.
* **Run as Desktop App (Dev)** : compile le backend Rust/Tauri et lance le jeu dans une fenêtre de bureau native. Si votre template ne cible pas les plateformes de bureau ou mobiles, cette configuration ne sera pas proposée.

### Personnaliser le style

L'interface utilisateur du template repose entièrement sur [shadcn/ui](https://ui.shadcn.com/), ce qui permet de personnaliser les couleurs du thème sans modifier le code des composants.

Ouvrez le [générateur de thèmes shadcn/ui](https://ui.shadcn.com/create?template=vite\&base=base\&preset=b1s9eyGkS), ajustez les couleurs à votre goût, puis accédez à la section **Copy** de la page pour copier la commande CSS générée. Exécutez cette commande depuis la racine du projet :

```npm
npx shadcn@latest add <paste-the-generated-command-here>
```

Après l'avoir appliquée, il est conseillé de reformater les fichiers source :

```npm
npm run format
```

Pour aller plus loin — polices, styles globaux et autres — consultez <DynamicLink href="/start/interface-font">Styles et polices</DynamicLink>.

### Écrans du template

Le template contient plusieurs écrans prédéfinis qui couvrent les éléments essentiels d'un visual novel. Chaque écran est un composant React associé à une route gérée par TanStack Router.

* **Menu principal** (`/`) — le premier écran affiché au joueur lors du lancement du jeu. Il permet de démarrer une nouvelle partie, de reprendre une sauvegarde et d'ouvrir les paramètres.
* **Écran de narration** (`/game/narration`) — l'écran de jeu principal où s'affiche l'histoire. Il affiche les dialogues, les sprites des personnages, les arrière-plans et les choix.
* **Paramètres** — le panneau des paramètres ne possède pas de route dédiée. Il utilise plutôt les [Search Params](https://tanstack.com/router/latest/docs/framework/react/guide/search-params) pour se superposer à l'écran actuellement actif. Cette approche permet de conserver une URL simple, tout en autorisant le joueur à ouvrir les paramètres depuis n'importe quel écran du jeu et à naviguer entre leurs différentes sections (audio, affichage, langue, etc.) sans perdre le contexte de navigation précédent.
* **Écran de navigation** (`/game/navigation`) — uniquement pour *Point & Click*. Il permet au joueur de se déplacer entre les pièces et d'effectuer les différentes actions disponibles à l'emplacement actuel.
* **Écran de carte** (`/game/map`) — uniquement pour *Point & Click*. Il affiche la carte et permet au joueur de se déplacer d'un endroit à un autre. Il permet également de gérer plusieurs cartes.
