## Come utilizzare un template

Se stai leggendo questa pagina, probabilmente hai già generato un progetto da un template. Le sezioni seguenti ti guideranno nei primi passaggi per avviarlo.

### Configurazione iniziale

Apri la cartella del progetto con il tuo IDE. Gli esempi seguenti utilizzano [Visual Studio Code](https://code.visualstudio.com/).

Una volta aperto il progetto, VS Code suggerirà automaticamente alcune operazioni:

* **Installa le estensioni consigliate** — apparirà una notifica che ti chiederà di installare le estensioni consigliate per l'area di lavoro. Ti consigliamo vivamente di accettare. Se la notifica non appare, puoi installarle manualmente dal pannello Estensioni filtrando per le [estensioni consigliate](https://code.visualstudio.com/docs/editor/extension-marketplace#_recommended-extensions).
* **Esegui le attività di avvio** — VS Code potrebbe chiederti di eseguire le attività di avvio configurate, che installeranno tutte le dipendenze del progetto. Se preferisci procedere manualmente, esegui:

```npm
npm install
```

:::warning[Multipiattaforma]

Se hai scelto un template destinato a piattaforme desktop o mobili, dovrai installare le dipendenze aggiuntive richieste da [Tauri](https://v2.tauri.app/start/prerequisites/) (toolchain Rust e strumenti di compilazione specifici della piattaforma). Poiché Tauri si integra profondamente con l'ambiente di sistema, probabilmente dovrai **riavviare VS Code una o più volte** prima di poter avviare il progetto come applicazione desktop.

:::

### Avviare il progetto

Il template include una serie di **configurazioni di avvio** preconfigurate per VS Code. Se non le conosci, le configurazioni di avvio sono scorciatoie che indicano a VS Code come avviare il progetto (ed eventualmente collegare un debugger), così non devi digitare ogni volta i comandi nel terminale. Puoi accedervi dal pannello **Esegui e debug** (l'icona di riproduzione nella barra laterale sinistra, oppure premendo `F5`). Seleziona la configurazione desiderata dal menu a discesa nella parte superiore del pannello e premi il pulsante verde di avvio.

![Pannello Esegui e debug](/launch-configuration-dropdown.png)

Sono disponibili le seguenti configurazioni:

* **Debug Game**: è la configurazione che userai più spesso durante lo sviluppo: ogni volta che salvi un file, il browser si aggiorna automaticamente. Tieni presente che in questa modalità le animazioni potrebbero non essere perfettamente fluide e il caricamento degli assets potrebbe essere più lento rispetto alla versione finale pubblicata.
* **Debug Game Preview**: simula fedelmente il comportamento del gioco dopo la pubblicazione: le animazioni sono fluide, i tempi di caricamento sono realistici e le ottimizzazioni sono attive. Usa questa configurazione quando vuoi verificare che tutto abbia l'aspetto e il comportamento previsti prima della pubblicazione.
* **Run as Desktop App (Dev)**: compila il backend Rust/Tauri e avvia il gioco in una finestra desktop nativa. Se il tuo template non è destinato a piattaforme desktop o mobili, questa configurazione non sarà presente.

<Accordion title="Riga di comando" id="command-line">

Tutti i comandi devono essere eseguiti dalla directory principale del progetto.

**Sviluppo**

| Comando                     | Descrizione                                                                                                      |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `npm run dev`               | Avvia il server di sviluppo Vite e apre il gioco nel browser.                                                    |
| `npm run tauri:dev`         | Avvia il gioco come applicazione **desktop** (richiede il template multipiattaforma e l'installazione di Tauri). |
| `npm run tauri:android:dev` | Avvia il gioco su un dispositivo Android collegato o su un emulatore.                                            |
| `npm run tauri:ios:dev`     | Avvia il gioco su un dispositivo iOS collegato o su un simulatore.                                               |

**Compilazione e anteprima**

| Comando              | Descrizione                                                                                                               |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `npm run build:fast` | Compila solo l'applicazione web (senza Tauri). Rapido, adatto alla pubblicazione sul web.                                 |
| `npm run build`      | Compilazione completa: compila TypeScript, genera l'applicazione web e crea il pacchetto dell'applicazione desktop Tauri. |
| `npm run preview`    | Esegue `build:fast` e poi distribuisce il risultato localmente, simulando il gioco web pubblicato.                        |

**Assets e icone**

| Comando        | Descrizione                                                                                                                          |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `npm run icon` | Genera tutte le varianti dell'icona (PWA, desktop, mobile) da `public/icon.png`. Esegui questo comando dopo aver sostituito l'icona. |

| Comando             | Descrizione                                                                                                                                 |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `npm run ui:reinit` | Reinizializza [shadcn/ui](https://ui.shadcn.com/) da zero (reinstallando forzatamente tutti i componenti) e poi riformatta i file sorgente. |

### Personalizzare lo stile

L'interfaccia utente del template è realizzata interamente con [shadcn/ui](https://ui.shadcn.com/), quindi puoi personalizzare il tema cromatico senza modificare il codice dei componenti.

Apri il [generatore di temi shadcn/ui](https://ui.shadcn.com/create?template=vite\&base=base\&preset=b1s9eyGkS), regola i colori a tuo piacimento, poi vai alla sezione **Copy** della pagina per copiare il comando CSS generato. Esegui il comando dalla directory principale del progetto:

```npm
npx shadcn@latest add <paste-the-generated-command-here>
```

Dopo averlo applicato, è consigliabile riformattare i file sorgente:

```npm
npm run format
```

Per ulteriori personalizzazioni — caratteri, stili globali e altro — consulta <DynamicLink href="/start/interface-font">Stili e caratteri</DynamicLink>.

### Screen del template

Il template include una serie di screen predefinite che coprono le parti essenziali di una visual novel. Ogni screen è un componente React collegato a una route gestita da TanStack Router.

* **Menu principale** (`/`) — la prima screen che il giocatore vede all'avvio del gioco. Consente di iniziare una nuova partita, continuare una partita salvata e aprire le impostazioni.
* **Screen di narrazione** (`/game/narration`) — la screen principale di gioco in cui viene mostrata la storia. Mostra dialoghi, sprite dei personaggi, sfondi e scelte.
* **Impostazioni** — il pannello delle impostazioni non ha una route dedicata. Utilizza invece i [Search Params](https://tanstack.com/router/latest/docs/framework/react/guide/search-params) per sovrapporsi alla screen attualmente attiva. Questo approccio mantiene l'URL pulito e consente al giocatore di aprire le impostazioni da qualsiasi punto del gioco e di navigare tra le sezioni delle impostazioni (audio, visualizzazione, lingua, ecc.) senza perdere il punto in cui si trovava.
* **Screen di navigazione** (`/game/navigation`) — solo *Point & Click*. Consente al giocatore di spostarsi tra le stanze ed eseguire le varie azioni disponibili nel luogo corrente.
* **Screen della mappa** (`/game/map`) — solo *Point & Click*. Mostra la mappa e consente al giocatore di spostarsi da un luogo all'altro. Supporta anche la gestione di più mappe.
