## So verwendest du eine Vorlage

Wenn du diese Seite liest, hast du wahrscheinlich bereits ein Projekt aus einer Vorlage erstellt. Die folgenden Abschnitte führen dich durch die ersten Schritte, um es zum Laufen zu bringen.

### Ersteinrichtung

Öffne den Projektordner in deiner IDE. Die folgenden Beispiele verwenden [Visual Studio Code](https://code.visualstudio.com/).

Sobald das Projekt geöffnet ist, schlägt VS Code automatisch einige Schritte vor:

* **Empfohlene Erweiterungen installieren** — eine Benachrichtigung fordert dich auf, die für den Arbeitsbereich empfohlenen Erweiterungen zu installieren. Es wird dringend empfohlen, dies zu bestätigen. Wenn die Benachrichtigung nicht erscheint, kannst du sie manuell im Bereich „Erweiterungen“ installieren, indem du nach [empfohlenen Erweiterungen](https://code.visualstudio.com/docs/editor/extension-marketplace#_recommended-extensions) filterst.
* **Startaufgaben ausführen** — VS Code kann dich auffordern, die konfigurierten Startaufgaben auszuführen, die alle Projektabhängigkeiten installieren. Wenn du das lieber manuell erledigen möchtest, führe Folgendes aus:

```npm
npm install
```

:::warning[Plattformübergreifend]

Wenn du eine Vorlage für Desktop- oder Mobilplattformen ausgewählt hast, musst du die zusätzlichen Abhängigkeiten für [Tauri](https://v2.tauri.app/start/prerequisites/) installieren (Rust-Toolchain und plattformspezifische Build-Werkzeuge). Da Tauri eng in die Systemumgebung integriert ist, musst du **VS Code wahrscheinlich ein- oder mehrmals neu starten**, bevor sich das Projekt als Desktop-Anwendung starten lässt.

:::

### Projekt starten

Die Vorlage enthält mehrere vorkonfigurierte **Startkonfigurationen** für VS Code. Falls du sie noch nicht kennst: Startkonfigurationen sind Verknüpfungen, die VS Code mitteilen, wie dein Projekt gestartet werden soll (und optional einen Debugger anhängen). So musst du die Befehle nicht jedes Mal im Terminal eingeben. Du findest sie im Bereich **Ausführen und Debuggen** (über das Wiedergabesymbol in der linken Seitenleiste oder mit `F5`). Wähle oben im Bereich die gewünschte Konfiguration aus dem Dropdown-Menü aus und klicke auf die grüne Wiedergabeschaltfläche.

![Bereich Ausführen und Debuggen](/launch-configuration-dropdown.png)

Folgende Konfigurationen stehen zur Verfügung:

* **Debug Game**: Dies ist die Konfiguration, die du während der Entwicklung am häufigsten verwendest – jedes Mal, wenn du eine Datei speicherst, lädt der Browser die Seite automatisch neu. Beachte, dass Animationen in diesem Modus möglicherweise nicht ganz flüssig laufen und Assets langsamer geladen werden als in der endgültigen veröffentlichten Version.
* **Debug Game Preview**: Diese Konfiguration simuliert das Verhalten des Spiels nach der Veröffentlichung möglichst genau: Animationen laufen flüssig, Ladezeiten sind realistisch und Optimierungen sind aktiviert. Verwende diese Konfiguration, um vor der Veröffentlichung zu prüfen, ob alles wie vorgesehen aussieht und funktioniert.
* **Run as Desktop App (Dev)**: Kompiliert das Rust/Tauri-Backend und startet das Spiel in einem nativen Desktop-Fenster. Wenn deine Vorlage nicht für Desktop- oder Mobilplattformen gedacht ist, ist diese Konfiguration nicht vorhanden.

Alle Befehle müssen im Stammverzeichnis des Projekts ausgeführt werden.

**Entwicklung**

| Befehl                      | Beschreibung                                                                                                                     |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |

| `npm run tauri:dev`         | Startet das Spiel als **Desktop**-Anwendung (erfordert die plattformübergreifende Vorlage und eine installierte Tauri-Umgebung). |
| `npm run tauri:android:dev` | Startet das Spiel auf einem verbundenen Android-Gerät oder in einem Emulator.                                                    |
| `npm run tauri:ios:dev`     | Startet das Spiel auf einem verbundenen iOS-Gerät oder in einem Simulator.                                                       |

**Build und Vorschau**

| Befehl               | Beschreibung                                                                                                       |
| -------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `npm run build:fast` | Erstellt nur die Webanwendung (ohne Tauri). Schnell und für die Webveröffentlichung geeignet.                      |
| `npm run build`      | Vollständiger Build: Kompiliert TypeScript, erstellt die Webanwendung und paketiert die Tauri-Desktop-Anwendung.   |
| `npm run preview`    | Führt `build:fast` aus und stellt das Ergebnis anschließend lokal bereit — simuliert das veröffentlichte Webspiel. |

| Befehl         | Beschreibung                                                                                                                                 |

### Stil anpassen

Die Benutzeroberfläche der Vorlage basiert vollständig auf [shadcn/ui](https://ui.shadcn.com/). Du kannst daher das Farbschema anpassen, ohne den Code einer Komponente zu ändern.

Öffne den [Theme-Generator von shadcn/ui](https://ui.shadcn.com/create?template=vite\&base=base\&preset=b1s9eyGkS), passe die Farben nach deinem Geschmack an und wechsle dann zum Abschnitt **Copy**, um den generierten CSS-Befehl zu kopieren. Führe diesen Befehl im Stammverzeichnis deines Projekts aus:

```npm
npx shadcn@latest add <paste-the-generated-command-here>
```

Anschließend empfiehlt es sich, die Quelldateien neu zu formatieren:

```npm
npm run format
```

Weitere Anpassungen — Schriftarten, globale Stile und mehr — findest du unter <DynamicLink href="/start/interface-font">Stile und Schriftarten</DynamicLink>.

### Bildschirme der Vorlage

Die Vorlage enthält vorgefertigte Bildschirme, die die wichtigsten Bestandteile einer Visual Novel abdecken. Jeder Bildschirm ist eine React-Komponente, die mit einer von TanStack Router verwalteten Route verbunden ist.

* **Hauptmenü** (`/`) — der erste Bildschirm, den Spieler beim Start des Spiels sehen. Hier können Spieler ein neues Spiel beginnen, einen gespeicherten Spielstand fortsetzen und die Einstellungen öffnen.
* **Erzählbildschirm** (`/game/narration`) — der zentrale Spielbildschirm, auf dem die Geschichte dargestellt wird. Er zeigt Dialoge, Charakter-Sprites, Hintergründe und Auswahlmöglichkeiten an.
* **Einstellungen** — der Einstellungsbereich hat keine eigene Route. Stattdessen verwendet er [Search Params](https://tanstack.com/router/latest/docs/framework/react/guide/search-params), um sich über den gerade aktiven Bildschirm zu legen. So bleibt die URL übersichtlich, während Spieler die Einstellungen überall im Spiel öffnen und zwischen den Einstellungsbereichen (Audio, Anzeige, Sprache usw.) wechseln können, ohne ihren bisherigen Kontext zu verlieren.
* **Navigationsbildschirm** (`/game/navigation`) — nur für *Point & Click*. Er ermöglicht es den Spielern, zwischen Räumen zu wechseln und die am aktuellen Ort verfügbaren Aktionen auszuführen.
* **Kartenbildschirm** (`/game/map`) — nur für *Point & Click*. Er zeigt die Karte an und lässt die Spieler von einem Ort zum anderen wechseln. Außerdem unterstützt er die Verwaltung mehrerer Karten.
