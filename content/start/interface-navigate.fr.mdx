---
title: Naviguer/basculer entre les écrans UI
---

Pour naviguer entre différents écrans UI, il est nécessaire d'utiliser un système de routage. Un système de routage vous permet de définir des routes (ou chemins) pour différents écrans et de gérer la navigation entre eux.

## TanStack Router

<Accordions>

<Accordion title="Qu'est-ce que TanStack Router ?" id="what-is-tanstack-router">

TanStack Router est un système de routage pour les applications web qui vous permet de gérer la navigation entre différentes pages ou différents composants de manière simple et efficace. Il est conçu pour être flexible et facile à utiliser, offrant des fonctionnalités avancées telles que la prise en charge des paramètres dynamiques, la gestion de l'état du routeur et l'intégration avec des bibliothèques de rendu comme React, Vue et Angular.

</Accordion>

</Accordions>

Le principal avantage de TanStack Router est sa capacité à générer automatiquement la gestion des routes à l'aide de `createFileRoute`. Avec `createFileRoute`, vous pouvez définir vos routes simplement en créant des fichiers dans une structure de dossiers spécifique. Par exemple, si vous créez un fichier `about.tsx` dans le dossier `src/routes`, TanStack Router générera automatiquement une route pour `/about` qui affiche le composant défini dans `about.tsx`.

```ts title="src/routes/about.tsx"
import { createFileRoute } from "@tanstack/react-router";

export const Route = createFileRoute("/about")({ // [!code focus]
    component: About, // [!code focus]
}); // [!code focus]

function About() {
    return (
        <main className="page-wrap px-4 py-12">
            <section className="island-shell rounded-2xl p-6 sm:p-8">
                <p className="island-kicker mb-2">About</p>
                <h1 className="display-title mb-3 text-4xl font-bold text-[var(--sea-ink)] sm:text-5xl">
                    A small starter with room to grow.
                </h1>
                <p className="m-0 max-w-3xl text-base leading-8 text-[var(--sea-ink-soft)]">
                    TanStack Start gives you type-safe routing, server functions, and modern SSR defaults. Use this as a
                    clean foundation, then layer in your own routes, styling, and add-ons.
                </p>
            </section>
        </main>
    );
}
```

## Comment naviguer entre les écrans/routes ?

Pour naviguer entre les écrans/routes, utilisez la fonction de navigation fournie par votre système de routage.

:::tip[Modèles]

Dans tous les modèles, l'interface `StepLabelProps` est déjà étendue pour inclure une fonction `navigate`. Vous pouvez la trouver dans le fichier `pixi-vn.d.ts`.

:::

<Accordions>

<Accordion title="Initialisation" id="initialize">

Pour activer cela, la fonction de navigation doit être incluse dans l'<DynamicLink href="/start/labels#steplabelprops">interface `StepLabelProps`</DynamicLink>.

```ts tab="pixi-vn.d.ts"
import { narration } from "@drincs/pixi-vn";

declare module "@drincs/pixi-vn" {
    interface StepLabelProps {
        navigate: (route: string) => void;
    }
}
```

```ts tab="hooks/useGameProps.ts"
import { StepLabelProps } from "@drincs/pixi-vn";
import useMyNavigate from "./useMyNavigate";

export default function useGameProps(): StepLabelProps {
    const navigate = useMyNavigate();

    return {
        navigate,
    };
}
```

</Accordion>

</Accordions>

<Callout title="Test" type="info">

Si le `Game.testing` du plugin Vite.js (voir la section « Vite.js plugin » ci-dessus et l'Agent Skill
`pixi-vn-testing`) est utilisé pour permettre à un agent IA de tester le jeu, appelez
[`Game.testing.setProps`](/jsdoc/pixi-vn/index/namespaces/Game/namespaces/testing/functions/setProps)
ici aussi, afin que `navigate` (et tout ce que renvoie ce hook) reste disponible pour une session de test :

```ts tab="hooks/useGameProps.ts"
import { Game, StepLabelProps } from "@drincs/pixi-vn"; // [!code focus]
import useMyNavigate from "./useMyNavigate";

export default function useGameProps(): StepLabelProps {
    const navigate = useMyNavigate();
    const props = {
        navigate,
    };
    Game.testing.setProps(props); // [!code focus]
    return props;
}
```

</Callout>

<Callout title="ink" type="info">

Dans tous les modèles *ink*, une <DynamicLink href="/ink/hashtag">commande hashtag personnalisée</DynamicLink> a été introduite pour naviguer entre les routes. To do this, you need to use the following syntax:

```ink title="ink"
# navigate [route]
```

* `route` : la route/le chemin de destination. Par exemple, `# navigate /new-route`.

</Callout>

Lorsque vous créez un nouveau label, vous pouvez utiliser la fonction `navigate` pour basculer entre les routes :

```ts tab="content/labels/start.label.ts"
export const startLabel = newLabel("start", [
    ({ navigate }) => {
        navigate("/new-route");
    },
]);
```

## Autres fonctionnalités

<Accordions>

<Accordion title="Bloquer les boutons précédent et suivant du navigateur" id="block-back-forward">

L'utilisation des boutons précédent et suivant du navigateur peut entraîner un état incohérent du jeu. Cela s'explique par le fait que ces touches permettent au joueur de naviguer entre les routes, et non entre les `steps` narratifs.

Il est recommandé d'empêcher le chemin de changer lorsque le bouton précédent du navigateur est actionné. Il existe de nombreuses façons de procéder, mais l'approche suivante est suggérée :

Interceptez l'événement `popstate`, qui est déclenché après que le bouton précédent du navigateur a été actionné, et appelez `history.forward()` pour annuler la navigation. Pour permettre aux utilisateurs de revenir en arrière s'ils appuient deux fois de suite sur le bouton précédent, nous pouvons ajouter un nouvel état à la pile d'historique à chaque changement de route.

Par exemple :

```ts title="hooks/useConfirmBackNavigation.ts"
import { useLocation } from "@tanstack/react-router";
import { useEffect } from "react";

/**
 * useConfirmBackNavigation
 *
 * Prevent accidental browser "back" navigation.
 * Behavior:
 * - On each `href` change it pushes a history state (`pushState`).
 * - Listens for `popstate` and calls `history.forward()` to cancel a single
 *   press of the browser back button.
 * - If the user presses back twice in succession (i.e. the second press occurs
 *   before the first is handled), the browser will navigate back.
 *
 * Usage: call this hook at the app root to avoid unintended back navigations
 * (e.g. accidental taps or gestures). Returns `null`.
 */
export default function useConfirmBackNavigation() {
    const { href } = useLocation();

    useEffect(() => {
        const isInIframe =
            typeof window !== "undefined" && window.self !== window.top;
        if (isInIframe) return;
        const listener = () => {
            window.history.forward();
        };
        window.addEventListener("popstate", listener);

        return () => {
            window.removeEventListener("popstate", listener);
        };
    }, []);

    useEffect(() => {
        window.history.pushState(null, href, href);
    }, [href]);
}
```
